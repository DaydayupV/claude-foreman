# 模型档位

挑讨论和审查的席位、给角色模式分配角色（见 `references/roles.md`）、`/foreman:setup` 选推理强度时用档位：先看档位，决定能不能扮需要复杂思考的角色；再看长处和短处，在同一档里挑更合适的。

## 从哪里拿档位
- `config` 输出的 `resolved_modules` 里，每个候选带一个 `tier`：`strong`、`mid`、`weak`，查不到为 `null`（未评级）。挑席位时先看它。
- 长处、短处、综合分用 `node "<脚本路径>" tiers` 查：不带参数列出当前配置在用的模型；`--model <名字>` 查任意模型（Claude Code 自己那席用系统提示里的模型 ID 查，比如 `tiers --model claude-opus-5-5`）；`--all` 列出全部；`--format md` 输出表格。
- 模型名的写法（服务商前缀、大小写、别名、加速版和免费版）由脚本按 `scripts/models.json` 的身份表归一，不用自己对照。

## 数据从哪来
- 分数来自 LiveBench（https://livebench.ai）：综合分和七个单项（Agentic、设计、编程、浏览器操作、数据分析、研究、推理）。数据在 `scripts/model-tiers.json`，`tiers` 输出里的 `source` 和 `checked` 写明是哪一期。
- 有几个模型这一期不在榜上，沿用旧档位表的档位和长短处（`source` 为 legacy），没有分数。

## 怎么用
- **档位按综合分划分**：强 ≥ 84，中 75–84，弱 < 75。档位只作参考，不是能不能参加的资格：需要复杂思考的角色先给强档（每个角色的建议档位见 `references/roles.md`），达不到建议档位的模型也能扮，但只作第 1 轮的广度席。
- **长处和短处是和同档模型比出来的**：某一项比同档模型的中位数高 5 分以上算长处，低 5 分以上算短处，低 15 分以上算"很弱"。所以长处只在同档里比较：比如两个强档模型抢"数据分析师"，选数据分析更突出的那个。不要因为一个弱档模型某个单项高，就把核心角色唯一的一席给它。`top` 是这个模型在全榜排第一的单项。
- **Agentic 分受接入方式影响**：同一个模型经 Codex、opencode、pi 调用，表现可能不一样。讨论里只有 Codex 能跑命令，所以"实证核查"这类角色先看工具能力，再看这一项。
- **未评级的模型**（`tier` 为 `null`）：同系列（`tiers` 输出里的 `family`）更新的版本是弱档的，按弱档算；其他按中档算。弹窗里标明"未评级"，由用户更正。
- **用户的看法优先**：偏好文件里写了对某个模型的判断（比如"把 kimi-k2.6 当强档"），按偏好文件来。偏好文件可以引用本地实测（`cli.mjs stats`：核实成立和误报的条数、只有它发现的条数、返工率）来改档位；脚本只给数据，不自动排名，也不替你挑人。

## 维护
LiveBench 几个月就会变，每次发版前更新一次：在 LiveBench 网页上复制整张表格存成文本文件，运行 `node tools/import-livebench.mjs --input <文件> --date <日期>`，看它列出的新增、更新、档位变化和对不上的名字。对不上的名字要收录时，先在 `scripts/models.json` 里加这个模型（或者给已有模型加 `board_names`），再导入一次。
