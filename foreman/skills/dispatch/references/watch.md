# 实时查看和网页看板

派出之后让用户看到实时进度。网页看板开着时（`dispatch.watch.web` 为 `true`），SKILL.md"派出时"那几条就够了，这一篇只在用户问看板、要回放、或者看板服务没起来时读；网页看板关着、要开终端实时查看时，第一次派出之前读这一篇。

## 用哪个入口
开关在 `dispatch.watch` 里，按 `web` 决定：
- **`web` 为 `true`（网页看板开着）**：只用网页看板，不主动开终端实时查看。派出后在告诉用户"已派出"的那句话里附上看板链接，见下面的"网页看板"。用户想在终端里看时，用 `/foreman:watch`。
- **`web` 为 `false`**：`terminal` 为 `true`（默认）时，任务在后台启动以后自动打开终端实时查看，并把终端面板弹出来，见"终端实时查看"；`terminal` 为 `false` 时不开，只告诉用户可以用 `/foreman:watch` 查看。

## 终端实时查看
- **先打开终端面板，再开标签页**（Claude 桌面版，这一步不能省：开标签页不会自己弹出面板）：先调用显示面板的工具（名字带 `show_pane`，和 `run_in_terminal` 一起用一次 ToolSearch 加载），`pane` 填 `terminal`，不填 `tab_id`；等它返回后再用 `run_in_terminal` 开标签页。面板开着时，新开的标签页会自动切到前台，watch 开头几秒的启动动画用户能从头看到；反过来先开标签页再显示面板，两次调用之间常常隔十几秒，面板出来时动画已经放完了。没有显示面板的工具就直接开标签页。
- **用 `run_in_terminal` 打开**：运行 `node <记录目录>/watch.mjs --run <run_id>`，标题写"<模型>：<短标题>"。讨论和审查都在计划的组里，只开一个标签页：`node <记录目录>/watch.mjs --group <组名>`，标题写"讨论：<短标题>"或"审查：<短标题>"；组视图里 Claude Code 席排在最前（席位号 0），和外部席一样显示报告的结论。并发拆分的执行组也是 `--group <组名>`，标题写"执行：<短标题>"。记录目录默认是 `~/.claude/foreman/runs`，在 Windows 上写成 `C:\Users\<用户名>\.claude\foreman\runs`，以 `config` 的输出为准。这个启动器由脚本自动生成，插件路径含非 ASCII 字符时也能满足 `run_in_terminal` 只接受 ASCII 的要求。`config` 输出里 `watch_launcher_ascii` 为 `false` 时（记录目录路径含中文等非 ASCII 字符），`run_in_terminal` 会拒绝这条命令：改为把命令放在代码块里发给用户，请用户在自己的终端里运行，并转告 `check` 输出里 `watch.fix` 的处理办法。
- run_id 在启动后后台输出的第一行（"run dir …/<run_id>"）里。不加 `--run` 时它会跟踪正在运行的任务，但其他会话可能也在跑任务，所以尽量指定。
- 标签页开好后，再调用一次显示面板的工具，`pane` 填 `terminal`、`tab_id` 填刚才的 tab_id，确保面板停在这个标签页上（中途用户切走了面板，或者面板被别的面板挡住时，这一下能切回来）。然后把标签页链接 `[<标题>](#terminal/<tab_id>)` 发给用户。
- **没有 `run_in_terminal` 时**（比如命令行版 Claude Code），把完整的 watch 命令放在 bash 代码块里发给用户，请用户在另一个终端里运行。
- 任务结束后实时查看停在画面里：用户可以翻看完整记录，组视图里按席位号打开某一席；按 q 离开后记录留在标签页里供回看。不要关闭标签页。续接时：组视图（`--group`）会自己跟到组里每个任务的最新一轮，组里的任务续接不用新开标签页；讨论的下一轮也在原来的组标签页里看，需要单独看这一轮时才新开一个 `--group <组名>`，标题写"讨论：<短标题>（第 N 轮）"。不在组里的单任务续接时新开一个标签页，用 `resume` 输出的新 run_id；原来的单任务标签页底部会提示已续接，按 n 也能跟过去。终端面板最多开 6 个标签页：满了时先关掉最早的、已经结束的实时查看标签页，再开新的。
- 默认是简洁显示。用户要看完整细节时，加 `--verbose`。

## 网页看板
派出命令（`run`、`resume`、`discuss`、`review`、`image`）启动时，在第一行之后紧接着输出一行 `foreman: web board <url>`，是这个对话的看板地址。每次派出以后，都在告诉用户"已派出：…"的那句话里附上它，写成 `[网页看板](<url>)`，比如"已派出：gpt-6-astra low · Codex CLI，等级 simple · [网页看板](<url>)"。不只是用户发消息后的第一次派出：完成通知唤醒后接着派的、返工续接的、讨论下一轮的，也都要附；几个任务一起派出、写在同一句话里时附一次。最后向用户汇报时再附一次。这句话要写在回复的正文里，写在思考里用户看不到；派出后同一轮里接着做别的（继续调用工具）时也一样，先把这句话作为正文写出来，再调用下一个工具。插件的钩子在派出命令运行前也会显示这个链接，但桌面版把它折在工具调用里，不显眼，不能代替你写。

没有那一行时（看板服务没在跑），以及用户问看板在哪、说没看到链接、要你给链接时，运行 `node "<脚本路径>" board`，读输出的 JSON：
- `enabled` 为 `true`：把 `url` 写成链接发给用户，比如 `[网页看板](<url>)`，说明点开会在本机的默认浏览器里打开，直接进入这个对话的看板，再往外缩能看到本机所有对话。**不要用任何浏览器工具替用户打开**（应用里的网页面板、Claude in Chrome 都不用），由用户自己点链接。
- `enabled` 为 `false`：只写一句"网页看板未开启"，可以顺带说明用 `/foreman:setup` 或在配置里把 `dispatch.watch.web` 设成 `true` 打开。
- 看板服务是这台电脑上所有对话共用的：`board` 发现服务已经在运行就直接复用（`started` 为 `false`），没在运行才在后台启动一个。命令报错时转告错误，不影响派出的任务。服务 30 分钟没人看、也没有任务在跑会自己退出，插件被卸载或更新后也会退出；用户要马上关掉时运行 `board --stop`。
- 看板只做直播。用户要把已经结束的对话按时间重新播一遍查问题时，用 `board --replay <对话 id、run_id、组名或 all> [--speed <倍数>] [--maxgap <秒>]`：它另起一个临时回放服务，输出的 `url` 同样写成链接发给用户。记录太大（超过 256 MB）或找不到目标时，把报错原文转告用户。派活时不用它。
