# 图像模块：路线、分工和流程

认出是图形工作、弹路线窗之前读这一篇。提示词、背景、格子模板、用在代码作品里的整套做法和改图见 `references/image-assets.md`（下面写"第 N 节"的都指那一篇），`assets` 子命令的参数见 `references/assets-cli.md`。

出图和手画都走图像模块，不用 `run`。图像任务不分等级，`plan`、`image` 和续接都不写 `--level`，推理强度用图像格子里写的；出图质量取决于图像模型，和推理强度关系不大。同一件事还要改代码（比如把图接进页面）时，代码部分另按执行定级。只看截图做视觉检查（`review --target visual`）属于审查，不走这里。

## 两格
- 出图交给 `resolved_modules.image.generate` 里的协作方，手画（会弯的部件、纯矢量）交给 `resolved_modules.image.draw` 里的，推理强度用它在那一格写的。generate 只挑能出图的（`capabilities.images` 为 `true`，目前只有 `codex cli` 类型），draw 挑能执行的；有几个候选时按 `references/seats.md` 挑。
- **格子关着时**：generate 是 `null` 时用户关掉了出图，告诉用户这次不出图，不要改用别的办法凑；draw 是 `null` 时，会弯的部件和纯矢量绘制由 Claude 自己画。`image_configured` 为 `false`（配置里还没有图像块，比如从旧配置改写过来的）时两格都按关着处理，建议用户运行 `/foreman:setup` 加上图像两格。

## 流程和规则
1. **范围**：要模型画的图形内容都走这里，不论最后交付的是位图，还是 SVG、HTML、canvas 或动画：照片、插画、贴图、精灵图、封面和主视觉、角色和吉祥物、场景、插画风图标、UI 组件的视觉、要切成单个素材或转成 SVG 的素材（包括 SVG、HTML、canvas 作品和动画里整块使用的插画）、给现有图片去背景、修改现有图片，以及照定稿图手画会弯的部件、纯矢量绘制。用户明确要求手写 SVG 或纯代码时不出图（仍然弹窗，路线 ④）。
2. **弹窗选路线**：每个新的图形交付物开工前，用 AskUserQuestion 弹窗让用户选路线，`dispatch.auto` 开着、用户的原话已经定了路线也一样。路线决定用到哪几格：

   | 路线 | 做法 | 用到的格子 |
   |---|---|---|
   | ① 位图 | 新出图，或者改已有的图，交付位图 | generate |
   | ② 位图 + 矢量混合 | 一张定稿图；整块动的部件由 Claude 用 `assets layers` 裁出来；会弯的部件照定稿图手画成 SVG | generate、draw |
   | ③ 纯矢量，先出参考图 | 参考图只用来定风格，成品全是路径，不嵌位图 | generate（只出参考图）、draw |
   | ④ 纯矢量 / 代码 | 不调用出图工具 | draw |

   - **弹窗的写法**：问题里带"图像路线"四个字（比如"图像路线：首页吉祥物这次怎么做？"），header 写"图像路线"；四个选项的 label 以 ①②③④ 开头，照上表写（比如"② 位图 + 矢量混合"）。脚本靠这两点认出路线弹窗、读出选的是哪条。
   - 弹窗里写明（写在问题或各选项的说明里）：出图、手画各用哪个模型；参考图会不会上传给模型服务；返工规则：不设出图次数上限，同一个问题连续三次重出都没有改善就停下来问用户，用户给了上限就按用户的。要不要出几张候选图，在同一个弹窗里另问一题。
   - 用户的原话已经定了路线时照样弹窗，把那一项排在第一位，label 末尾加"（你已选定）"。
   - 不再问：同一个交付物的返工、局部重出、补丁、技术性重试。要重新问：换路线、加新的交付物、扩大范围、换协作方或厂商。
   - 同时还要确认角色分配时，两件事合成一次弹窗。
3. **确认凭据**：插件的钩子把路线弹窗的问题和回答按 Claude 会话记在 `~/.claude/foreman/answers/<会话>.jsonl`。`plan --module image` 只看这个会话里最近一次路线弹窗：用户选的就是 `--route` 那条才建计划；用户取消了、还没选、选了 Other 写了别的话，或者选的和 `--route` 不一致，都不建计划，这时按用户的回答处理，需要时重新弹窗。一次回答可以支撑这个交付物的几份计划（比如路线 ② 的 generate 和 draw）。answers 文件只由钩子写，不要自己写、改或删：这份凭据防的是漏问，挡不住伪造，伪造就是违规。已经弹过窗、用户也选了，`plan` 还说没有回答时，多半是钩子没生效（比如插件的钩子被禁用）：如实告诉用户，不要改用 `run` 出图。钩子 2026-10-19 在桌面版实测过；命令行版没有实测。
4. **建计划**：用到哪格建哪格的计划：`plan --module image --cell <generate|draw> --route <路线号> --group <组名> --seat <代号> --why "<理由>"`（这一格按场景配了时再加 `--scene <场景> --scene-why "<依据>"`，见 `references/config.md` 的"场景"）。路线 ① 只建 generate；路线 ② 先建 generate（定稿图、背景板、局部变体），取件之后再建 draw（会弯的部件）；路线 ③ 先建 generate（只出参考图），再建 draw（纯矢量成品）；路线 ④ 只建 draw。一个交付物用到两格时每格各建一份计划，凭的是同一次路线回答。
   ```bash
   node "<脚本路径>" plan --cwd "<项目目录>" --module image --cell generate --route 2 --group <组名> --seat <generate 格子里的代号> --why "<理由>"
   ```
5. **启动**：`image --plan <plan_id> --seat 1 --brief <任务说明> --title <短标题> --scope <输出目录> [--track "<路径>"] [--effort <强度>]`，不写 `--level`。不要用 `run` 出图：脚本会在结果里提示"出图没有走图像模块"。启动后照 SKILL.md 的"派出时"告诉用户、附看板链接。出一张图要几十秒，这段时间实时查看停在上一步是正常的；图生成后时间线上会出现一行"Generated image …"。
6. **分工**：画什么由 Claude 定：主体、风格、用途、画幅、部件清单和名字、色板、定稿图；图上要有文字的，给出原文、要求照抄。Codex 只出图。去背景、切部件、从定稿图取件、命名、减色、矢量化和检查由 Claude 在本机跑 `assets` 子命令（见 `references/assets-cli.md`），不派出去，也不让 Codex 做；会弯部件的描图和变形是例外，交给 Codex，它自己跑 `assets trace`、`capture`、`playback` 自查。不许用脚本冒充模型出图，但可以用脚本处理模型出的图。
7. **同源取件：Codex 只画整张画面，不画单个部件**：图像模型画不准关节转轴、和代码画的东西的接触点、两次出图之间的接缝，单独取出的部件也会被放大、重画（2026 年 10 月实测偏差动辄是部件长度的几成，单独取出的部件被放大 1.09–2.06 倍）。所以要相接的两块像素必须来自同一张图，或者一侧是代码画的。作品里的部件都从定稿图上取：整块动的由 Claude 用 `assets layers` 按原位置裁出；本身要弯、要和代码画的东西精确接触的，交给 draw 格子照定稿图描成路径、写好变形；物理、机械、文字、UI 用代码画。Codex 只出四种图、部件怎么取，见第六节的总则和第 1 步。路线 ③、④ 的成品全是路径，不能拿嵌进 SVG 的 PNG 冒充矢量，路线 ④ 也不出位图。
8. **定稿图先给用户看**：按第六节第 2 步的定稿图模板写（只写画面上的要求，不写部件名单和拆分方法），用户认可后再出背景板、取件。接缝放在定稿图里已有的遮挡物边上。不让模型单独取出部件、删掉部件再收边，或者补画角色身上被挡住的部分。表情（眨眼、张嘴）在定稿图上局部改图，用 `assets patch` 只叠补丁：不整张换图，也不描。
9. **会弯部件的手画**：派给 draw 格子（路线 ②）。Claude 先取好件，再按第六节第 6 步的模板写任务说明：输入、固定好的页面框架和接口、转轴、动作公式、接缝要求和自查要求。交回后 Claude 自己截图、量指标验收，不采信它的自查结论。2026 年 10 月对照试片里，两边的指标打平，盲看时 Codex 手画的更自然。纯矢量路线（③、④）的绘制也派给 draw 格子。
10. **动手前告诉用户**哪些部件整块动、哪些交给 Codex 描成路径弯曲、哪些代码画，以及为什么。**动画交付前**用 `assets playback` 检查一圈播放（闪动、首尾衔接、跳帧），把生成的播放文件给用户看；连续播放有人看过才算验收完。
11. **任务说明**：
    - 写明调用方式（参数见第一节）。全新出图：`tools.image_gen__imagegen({prompt, transparent_background})`。改图、照参考图出图、拆图、分层：再加 `referenced_image_paths: ["<绝对路径>", …]`，提示词里用 "Image 1"、"Image 2" 按顺序指代。不传这个参数，工具会当成全新出图，参考图不起作用。参考图会上传给模型服务，敏感或未授权的图不要用。
    - 不写像素尺寸，只写画幅（1:1、3:2、2:3、3:1）；要别的尺寸，用 SVG 或者交付时另行缩放。
    - 要透明背景的素材写 `transparent_background: true`，背景、间距、风格和禁止项照第二、三节的模板写。
    - 两个以上部件：用第四节的格子模板命名，不按排列顺序命名：模型会打乱顺序。
    - 写明每张图保存到项目里的路径，原图照原样复制，不转换、不压缩。用户没要求变体时，每张源图只出一次。
12. **验收**：
    1. 结果里的 `module`、`step`、`route` 写明这是哪一格、哪条路线的任务。`generated_images` 列出这一轮新出现的图片原文件，`image_calls` 列出每次出图实际传的参数（从 Codex 的会话记录里读出）。该传参考图的步骤在 `image_calls` 里没有 `referenced_image_paths`，说明参考图没起作用，要返工（`warnings` 会提示）。两个字段都没有时，出图来源未经验证，先查记录目录和输出再下结论。`warnings` 里说路线 ④ 出了位图、路线 ③ 或 ④ 的 SVG 里嵌了位图（`<image>`）的，按返工处理。
    2. 要切图或矢量化的素材跑 `assets cut`：结果的 `checks` 里有 `fail` 的直接返工；`needs_review` 的项由 Claude 看图判断。
    3. 用 Read 看图（切过的看 `sheet.png` 对照拼图）：每一格是不是那个部件，细节、风格和配色对不对，图上的文字是否照抄。
    4. 手画（draw）交回的按第六节第 6 步验收，并照 `references/acceptance.md` 看 diff。
13. **返工**：用 `resume --run <run_id> --brief … --reason rework` 续接原来的图像任务，不写 `--level`，也不再弹窗。出图不设固定次数，不合格就重出，每次重出都要改点什么（提示词、参考图、改动范围），不原样重试。重出门槛见第六节第 9 步，主要有三条：定稿图里会动的部件被别的部件压住、中间没有描边或遮挡物隔开；背景板或局部变体测出的对齐（`measured`）偏移超过 3 像素或缩放偏离超过 1%；背景板里还留着主体的残影。动起来接缝错开、线宽突变不是出图的问题：部件同源，本来是对齐的，要改变形代码（支点、权重、位置），不放大手画部分去盖；Codex 写的变形按 `references/acceptance.md` 的"返工"返工。自带命令报"拿不准"时按门槛处理，不另写配准或拟合脚本绕过去。同一个问题连续三次重出都没有改善时停下，把问题、试过的做法、已经出了几次图和可选的做法交给用户决定；用户给了出图次数上限时按用户的。出图不套用"返工"里由 Claude 接手的规则：Claude 不能出位图，也不许用脚本冒充模型出图。局部返工把原图作为参考图传入，提示词写"只改 X，其余不变"（第七节）；交付时只替换被改的那个部件，其余部件沿用上一版的文件。
14. **矢量化**：只有扁平、颜色少的素材转 SVG（第六节第 7 步）。角色、带渐变或细节多的画默认保留 PNG，用 `<image>` 嵌进 SVG 或页面，交付时告诉用户这部分不是纯路径；这是路线 ①、② 的做法，用户选了 ③ 或 ④ 时不能这样交付。
