# 验收和返工

收到执行任务或图像任务的结果、开始验收之前读这一篇。Claude 自己做的执行工作也按这里验收。图像任务另有自己的验收项和重出规则，见 `references/image.md`；结果不是正常完成（卡死、额度用完、要人回答等）时先看 `references/recovery.md`。

## 验收（每次必做）
1. 先看 `status` 和 `report.status`：不是 `completed` 就先读 `open_issues`。正常结束、却没交回合格报告的任务，status 和实时查看显示 "no valid result"，按失败处理。
2. 读 `run_dir/diff.patch`（这个任务的补丁；别的任务同时改的文件在 `diff.all.patch`），并核对 `changes.files`：
   - 有没有改到范围外的文件；`report.files_changed` 和实际改动是否一致。
   - `by` 为 `reported` 的文件，对照 diff 确认确实是这次任务该改的即可。`by` 为 `unknown` 的文件，可能是 Claude 自己、其他会话改的，也可能是协作方用命令写了却没报告。先弄清是谁改的，**不要直接还原**。其中标了 `group_run` 的落在同一目录下另一个同时运行的执行任务的写入范围里、又不在这个任务自己的范围里，多半是它改的，归到它验收（只在 `diff.all.patch` 里）。`changes.unstable_files` 里的文件拍快照时一直在被改写，改动没法比较：不能据此认定它们没变，要自己看一眼（文件多时这里只列前 20 个，完整列表在 `changes.unstable_list` 指向的文件里）。
   - 逻辑对不对，有没有过度防御、多余抽象、冗余测试。
   - **有没有做过头**：实际改动明显超过"规模"一节的预计（比如两倍以上），或者出现了没要求的参数、配置项、抽象层、兼容分支、测试。小处 Claude 直接删减；多的话用 `resume --reason rework` 返工，在返工说明里列出要删掉的东西。
   - 命名、注释和提示文字是否符合任务说明，是否说人话：命名是否直白、前后一致；注释和提示文字能否一眼看懂，有没有啰嗦、翻译腔、过度注释。不合格的小地方 Claude 直接改，不必返工；文字问题多的，在返工说明里给出改好的原文。
   - 只追踪工作目录内的改动；如果任务涉及工作目录外的路径，要另外检查。
3. **实际运行验证**：在最终版本上跑一次"最终验证"里的全量测试、构建或脚本，不能只看协作方自己说"通过了"。协作方已经跑过的定向测试不用单独再跑，全量覆盖了它们；全量失败、修复后或者又改了东西，照常重新跑。协作方事件流里的退出码不能代替这一步：有的是按工具状态合成的，复合命令和输出重定向也会掩盖失败。
4. **没有系统沙箱的执行**（结果里 `isolation` 为 `tools`，目前是 opencode 和 pi）要多看几眼：
   - `run_access` 为 `edit` 时，它不能运行命令：测试和脚本一律由 Claude 自己跑，报告里写"已通过"的也不算。
   - `run_access` 为 `shell` 时，它的命令能碰到工作目录以外的地方，改动追踪看不到那里。diff 要逐个文件看；任务涉及外部路径、安装依赖、联网的，要单独核对它实际做了什么（`run_dir` 里的 `opencode.jsonl` 或 `pi.jsonl` 有它跑过的每条命令）。
   - 写文件的工具事件算改动归属的证据（`by: agent`），报告里自称改过的不算。
5. 验收通过（包括返工之后），通常接着按审查定级（SKILL.md 的"定级"）；效果还需要和其他模型讨论的，先按讨论定级。审查是 0 级的，直接向用户汇报。

## 返工
- 不合格时用 `resume --reason rework` 返工一次，在返工说明里写清楚哪里不对、要怎么改。原因是任务难度估低了的话，返工时把等级升一级（simple → normal → complex）；升上去的那一级在配置里是 `"claude code"` 时不再续接，由 Claude 自己接手；升上去的那一格里没有原来的协作方、有别的必选，或者原来的任务是计划里的一席时，脚本会拒绝续接，这时按新等级重新派出一个任务（照常挑人，算这一次返工）。其余情况沿用原来的等级。图像任务不分等级，续接沿用原来的格子，不写 `--level`。
- 续接只能接最新的一轮，而且要等它结束：对还在运行、或者已经续接过的任务，脚本会拒绝，报错里给出最新一轮的 run_id。续接沿用原来的任务组（不能用 `--group` 改组）和 `--add-dir`；Codex 续接时，额外目录和 `~/.codex/config.toml` 里 `[sandbox_workspace_write]` 配的可写目录合在一起传，那一项读不懂时不传，脚本会提示额外目录这次没生效。
- 续接要写 `--level`（图像任务除外），上一轮的协作方要在这一格的候选里；点名派出的任务（结果标 `outside_cell`）不受这一条限制，续接沿用点名的那个协作方。换了等级续接时，新格子还有别的必选会被拒绝；计划里的席位不能换等级续接，要换就按新等级重新建计划。模型按新给的等级重新确定，所以返工升级时可能换成另一个模型；配置里哪里都没写模型时，沿用上一轮的模型。
- 返工后还不合格，或者协作方超时、报错，由 Claude 自己接手完成，并告诉用户原因。出图除外，见 `references/image.md` 的"返工"。
- 原任务之外新加的需求不是返工，也不续接：当作新任务定级、另派。分界看原任务说明：目标和完成标准里写了的，换个做法达到它是返工；没写的、或者写明这次不做的，是新需求。
