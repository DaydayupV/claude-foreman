# board 前端建设计划

2026-10-22 拟

## 一、现在到了哪一步

单对话看板的主体已经完成：
- 星图版面、光路和统一平滑。
- 派发流程动画：建计划拉起席位、准入闸、交叉挑错、裁决。
- 产出框从汇聚到读走的生命周期；组的进场和离场；刻度带循环滚动。
- 用量表，以及按原生终端规则显示的终端区。

多对话的宇宙层（A–F）、模块动效（G）都已完成，H 步已接进插件（见下面的"H 步做了什么"）。

## 二、目标：一个总前端，三级放大

```
宇宙（本机所有 Claude Code 对话） → 星系（一个对话的概况） → 看板（现在这套）
```

- 打开页面先看到宇宙。滚轮放大，或者点一个星系，就逐级飞进去，最后变成现在的看板。
- 同一时刻只挂一个完整看板，所以对话再多也不卡。
- 底部的用量表和终端区跟着当前所在的对话切换。

## 三、各层画什么

### 宇宙层

**布局**
- 每个项目（工作目录）是一团星云，同一项目的对话聚在一起；每个对话是一个小星系。
- 位置固定：按 id 算出来，刷新页面或者新增对话时，已有的星系不挪位置。

**星系的样子**
- 中心是一颗 Claude Code 亮核。
- 正在干活的协作方是绕着亮核转的星，用模型色系。
- 一个派发组是一圈轨道。

**状态**

| 状态 | 怎么认出来 | 画法 |
|---|---|---|
| 空闲 | 一段时间没有新记录 | 暗，慢慢自转 |
| 思考中 | Claude Code 正在输出 | 亮核脉动 |
| 派发中 | 有协作方在跑 | 轨道亮起，星在转，粒子流回亮核 |
| 等你确认 | 有还没回答的弹窗（角色、路线等） | 琥珀色呼吸光环，列表里置顶 |
| 出错 | 协作方失败、额度用完 | 红色闪一下，留一个小红点到下一轮 |

**标签和范围**
- 远看只显示项目名，放大到一定程度再显示对话标题。
- 默认只画最近 24 小时有活动的对话。更早的缩成背景星尘，不画细节；这个时间范围可以调。
- 没派过活的普通对话也画，但只有亮核没有星，画得小一些。

### 星系层（宇宙和看板之间）

- 放大到一个星系时，显示：
  - 标题；
  - 当前在做什么，一句话，比如"讨论组 2 级 · 3 席进行中"；
  - 每颗星的模型名。
- 继续放大就进入看板：
  - 亮核移到 Claude Code 卡片的位置，各颗星落到对应角色卡的位置；
  - 然后完整看板淡入、星系淡出；
  - 退出时反过来。

### 看板层

现在这套不变。缩到最小以后再往外缩，就退回宇宙。

### 跨对话的动效

- **派活**：星系里长出新星，同时容量带上对应的格子亮起。
- **任务结束**：星收回亮核，格子熄灭。
- **弹窗等确认**：出现呼吸光环，对话在列表里跳到最上面。
- **失败**：星变红后熄灭，星系留下红点。

## 四、操作

- **滚轮**：连续缩放，跨层时自动过渡。进看板和出看板的阈值错开一点，避免在边界来回闪。
- **点击**：点星系或者列表里的对话，直接飞进去，约 0.8 秒。
- **退回上一级**：按 Esc，或者点左上角的路径"宇宙 › 项目 › 对话"。
- **刷新**：地址栏记住当前对话，刷新后停在原处。
- **看板里的现有操作**：刻度带滚动、折叠组等都不变。

## 五、侧边和底部

**对话列表**（左侧，可收起）
- 排序：等你确认 › 派发中 › 思考中 › 空闲。
- 每行显示标题、项目、状态点和正在跑的席位数。
- 点一下就飞进去。

**容量带**
- 每个协作方一行，有几个并发名额就画几格。
- 被哪个对话占着，格子就亮成那个对话的标记色；排队等名额的画在格子外面。
- 名额是全机共用的，所以这条只有在总前端里才看得全。

**用量表**
- 在宇宙层按对话列，每个对话一行，最后是合计。
- 进入看板后变回现在的按模型明细。

**终端区**
- 在宇宙层显示"选一个对话查看终端"。
- 进入看板后显示这个对话的终端，规则和现在一样。

## 六、前端要的数据（接口草案，A 步写成 PROTOCOL-v3.md）

**接口**
- `GET /sessions`：所有对话的摘要。
- `/stream?level=all`：摘要的增量，约每秒一次，只发有变化的对话。
- `/stream?session=<id>`：一个对话的详细事件，格式和现在一样。相当于把现在"按组、按运行"的范围换成"按对话"。

**摘要字段**
- 对话 id、项目目录、标题、状态、最后活动时间。
- Claude Code 用的模型、用量和费用。
- 正在跑和刚结束的运行：协作方、模型、所属组、模块、状态。
- 有没有等你回答的弹窗，以及最近的错误。

**容量**：每个协作方的并发上限、占着名额的运行（各属于哪个对话）、排队数。

**多对话回放**：所有对话共用一个时钟，按同一条时间线推进，用来演示样本。

**已知限制**：工具权限确认框不写进对话记录，所以看不出"在等你批准权限"，只能看出"有工具调用还没结果"。AskUserQuestion 弹窗（角色、路线）能看出来。

**性能优化**（2026-10-23）
- **限帧**：原来跟着显示器刷新率重画（144Hz 屏一秒画 144 次）。现在静止时约 30 帧；拖动、缩放、镜头在走、飞入飞出时约 60 帧。
- **画布**：宇宙层画布按 1 倍像素画；看不见的那层画布隐藏；页面滚到终端区时不画星图。
- **省掉重复排版**：全貌适配每帧只算一次，不再每帧多次读侧栏位置。
- **效果**：1920×1080、125% 缩放下，宇宙层每秒 JS 耗时约 314 → 57 毫秒（9 个对话），约 480 → 114 毫秒（27 个对话）；看板约 44 毫秒。

**F 步进展**（2026-10-23）
- **真实数据规模**：74 个项目目录、163 个对话记录（1.18 GB）；24 小时窗口内 33 个文件、295 MB，最大的 97 MB；729 个运行。
- **服务端**：
  - 首次读取 2.9 → 2.1 秒，读完后内存 235 → 161 MB：对话记录改成 8 MB 分块读、边读边汇总。
  - 每次轮询 55 → 8 毫秒：已结束、结果已读的运行不再每秒检查，事件流只读还在跑的运行。
  - 费用改成算得出的部分照加、另标 `cost_partial`：原来有一项算不出就整份显示未知。
- **两个对话同时派活**：
  - 这个对话派前端审查（gpt-6.1-sol + deepseek-flash/pi），另一个对话派 1 级讨论（gpt-6-astra + gpt-6.1-sol）。
  - 星图两个星系同时显示派发中；gpt-6.1-sol 的名额 2/4 分属两个对话；飞进各自的明细都对。
- **前端审查**（2 级，Claude Code 席 + gpt-6.1-sol + deepseek-flash）：去重后 9 个问题，全部由我修好。
  - 点星系跨一帧就失效；
  - 切换对话后回放估算用了上一个对话的缓存；
  - 宇宙层定格时看板没跟着定格；
  - 项目布局每帧重算；
  - 在跑席位数取自截断的摘要；
  - 宇宙层顶栏不更新；
  - 宇宙层复位按钮和 0 键无效；
  - 过渡中两边输入叠加；
  - 一帧算多次布局。
- **真实数据里发现的**：名额带同一模型几种接入方式名字一样，现在标出接入方式；宇宙层定格超过回放末尾时两边时刻不一致，现在都停在末尾。
- **性能**（真实数据）：宇宙层约 29 帧、每秒 JS 51 毫秒；看板 38 毫秒。
- **首次读取的内存**：按另一个对话的 1 级讨论结论（gpt-6-astra + gpt-6.1-sol，三方一致）改成按字节切行：
  - 每块 1 MB，只把完整的一行交给同一个流式解码器，没读完的半行留成字节片段；
  - 真实数据上峰值 241 → 113 MB，读完 161 → 107 MB，首次读取 2.0 秒。
- **开发环境的坑**：用后台命令启动的服务会在别的命令结束时一起收到 Ctrl+C 而退出（Windows 同一控制台）。长时间运行的服务要放在单独的终端标签页里。H 步由插件以独立进程启动，不受影响。
- **留待以后**：
  - 首次读取的 2 秒里服务不响应（改成异步分块才能解决，不降内存）；
  - 宇宙层文字在高分屏上略虚；
  - 飞入时亮核落点按空看板计算。

## 八、风险和对策

- **对话记录很多**（`~/.claude/projects` 里可能有上千个）：只按修改时间筛选，只读最近活跃对话的尾部，标题从记录里的标题行取。

- **画面复杂度**：宇宙层只用摘要数据、全部画在 canvas 上，不建 DOM 卡片，标签数量随缩放限制。只开一个详细数据流，标签页隐藏时停帧。
